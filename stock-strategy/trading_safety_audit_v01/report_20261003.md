## 本機狀態與下週啟動障礙

1. launchd 的 Bot 程序仍存在；最後交易心跳為
   `2026-10-02T01:13:45.466724+00:00`，狀態 `STOPPED_UNSAFE`。
   心跳記錄的交易子程序 PID 查無程序。**Bot 活著不代表交易在監控。**
2. 本地 execution store 仍 HALT，保有前次事故的舊錯配成交及未確認
   `SEND_PENDING` 委託，沒有 position checkpoint。這是本地紀錄，不是
   券商目前庫存證據；人工賣出不能自動令這些紀錄變成可信或 flat。
3. 部署 runtime 沒有 `position_baseline.meta.json`。現有 capture 規則
   會拒絕仍有本地策略部位或 active order 的帳戶；兩個臨時資料庫測試
   已重現，即使 mock 券商回傳 flat，也不會重設 baseline。
   這是正確的 fail-closed 阻擋，**不得刪資料庫／清 HALT／把未知曝險
   吸收成原庫存來繞過**。
4. 目前程式來源 checkout 與 Bot 指定 runtime 的 alias checkout 是
   不同實體目錄。兩個 CLI 預設可取得不同 directory lock，存在兩套
   控制器同時運作的配置風險。
5. supervisor ledger 有 10/2 16:13 的啟動事件，晚於當日收盤；它能證明
   曾啟動，不能證明 thread 現在健康，也沒有實際平倉成功證據。
6. 未發現獨立 watchdog／force-flat LaunchAgent；目前備援在 Bot daemon
   thread 內。電源檢查沒有交易專用 caffeinate assertion。其他 app 的
   防睡眠 assertion 不能作為交易時段的可靠防護。
7. 本機 Stage A `20261002` 封存驗證成功，30 檔唯一、TWSE／TPEx 兩個
   官方身分來源可讀；交易日曆含 10/5，前一交易日為 10/2。
   這項前置資料目前有效，但不能補足帳戶與執行缺陷。
